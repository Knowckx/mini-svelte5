# 开发约束

## 语言、框架与目录

- 使用 Svelte 5 与 TypeScript；组件状态沿用现有 runes 写法。
- 应用源码放在 `src/`，页面放在 `src/pages/`，项目内通用组件放在 `src/lib/`，静态资源放在 `public/`。
- 源码可使用 `@/` 引用 `src/`；新增别名时必须同步 `tsconfig.json` 与 `vite.config.ts`。
- 当前没有 URL 路由；主页面切换由 `@knowckx/infa-s5` 的 `BottomNavigator` 共享状态负责。

## 页面结构

- `App.svelte` 负责配置四个主页面和中央 FAB；FAB 是独立操作，不改变当前页面。
- 页面根节点使用纵向 flex 满高布局；顶部导航按页面需要提供，内容区使用 `min-h-0 flex-1 overflow-y-auto` 独立滚动。
- 底部导航由 `infa-s5` 提供 scoped CSS 和边框分隔，不在项目内维护平行样式。
- 全局 `<infa.Tip.UI />` 只在 `App.svelte` 挂载一次，页面和导航组件不得重复挂载。

## 包管理与样式

- 使用 pnpm；项目依赖父级 `../pnpm-workspace.yaml` 和本地 `@knowckx/infa-s5`，不能按独立 npm 包安装流程假设其可用。
- Tailwind CSS 4 由 `src/app.css` 导入；必须保留对 `@knowckx/infa-s5/dist` 的 `@source` 扫描，否则依赖组件使用的样式类可能不会生成。
- `@knowckx/infa-s5` 已从 Vite 依赖预构建中排除，调整本地包联调方式时需同时检查该配置。

## PWA

- PWA 使用提示更新模式；`PWAUpdateController.svelte` 负责 Vite 虚拟模块、更新策略和计时器清理。
- PWA 提示界面由 `infa-s5` 提供，项目只通过状态和事件与其交互，不在本地维护平行 UI。
- PWA 清单引用的图标必须存在于 `public/`，导航回退保持为 `/index.html`。
- 开发服务使用 HTTPS；移除该配置前需评估 PWA 本地验证影响。

## 可用命令

- 开发：`pnpm dev`
- 生产构建：`pnpm build`
- 预览已有构建：`pnpm preview`
- 构建并预览 PWA：`pnpm pwa`

## 静态检查、测试与提交前验证

- 当前 `package.json` 未定义格式化、lint、独立类型检查或自动化测试命令，仓库也没有 CI 配置。
- 项目现有的可用构建检查是 `pnpm build`。
- 当前未定义额外的提交前验证规则；涉及 PWA 的修改需要在安全上下文中人工验证。
